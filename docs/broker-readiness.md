# Broker readiness and recovery preservation contract

## Scope and capability truth

This rebuild is research/read-only by default. The local Python infrastructure probe is an explicitly permitted native-language external-service utility, not first-party web/control-plane code, a broker adapter, an HTTP API, or an execution service. It has no startup hook or web wiring. All future product access must cross the published Vertex oRPC contracts; do not import this utility into Cloudflare or expose a generic remote-command endpoint.

No securities orders, live arming, deployment, credentials changes, login triggers, account queries, or provider requests were performed in this phase. Source observations and inherited historical status do not establish the current deployed state. The single execution/risk owner remains the Quant VPS; no Cloudflare route, model, browser helper, login result, or infrastructure probe can authorize a trade.

## Four distinct capabilities

1. **Cached status:** reads only local persisted/cached state, including its timestamp, provenance, and staleness. It must not make SSH, broker, authentication, or restart calls. Missing/stale evidence is unknown, not healthy.
2. **Infrastructure observation:** opt-in SSH metadata reads using an existing trusted host entry and an existing SSH key. Host/OS/user command success and container-state counts establish metadata observation only. Running containers do not establish broker login, quote subscriptions, API handshake, native engine integration, or strategy readiness.
3. **Broker handshake/readiness:** a separate, explicitly authorized capability. It is not implemented by this probe and always reports `not_attempted`. Connecting even a nominally read-only client can create broker sessions or cause helper side effects; it is not a passive infrastructure read.
4. **Human-only recovery:** an explicitly confirmed mutation with a precisely scoped Gateway target, bounded request, durable cooldown and single-flight owner. Phone approval and secret entry remain human-only. This implementation supplies no recovery operation; its recovery state is `disabled`.

Unknown, disabled, unavailable, and incompatible are different facts. A metadata failure is not proof that the broker is logged out; metadata success is not proof it is logged in. Never turn these into one green “ready” indicator.

## Safe infrastructure utility

Public local entrypoint: `services/gateway/infrastructure_probe.py`.

- `probe_infrastructure(config, checks=DEFAULT_CHECKS, *, execute=False)` returns a sanitized dictionary. Configuration has exactly `host`, `user`, `port`, `known_hosts`, and `identity`; no passwords, environment dictionaries, shell fragments, command arguments, extra SSH options, or configurable timeouts are accepted.
- `main(argv=None)` is the CLI entrypoint. No arguments returns disabled without launching a process. Execution requires `--execute` and explicit `--host`, `--user`, `--known-hosts`, `--identity`; optional `--port` defaults to 22. Repeatable `--check` accepts only `hostname`, `os`, `user`, or `containers`. Unknown arguments and ambiguous abbreviations are rejected without echoing their contents.
- State is `unavailable | blocked | timeout | failed | observed`; fixed reason codes are `probe_disabled`, `invalid_configuration`, `invalid_checks`, `invalid_arguments`, `host_trust_unverified`, `command_timeout`, `ssh_or_command_failed`, `unexpected_metadata`, `local_tool_unavailable`, or `metadata_only`.
- Every result separately fixes `brokerHandshake: not_attempted`, `recovery: disabled`, and `trading: disabled`. `observations` contains only successful check states, an allowlisted OS family, and aggregate container counts by allowlisted lifecycle state. Partial observations may accompany failure; they do not upgrade the overall state. No raw stderr, usernames, hostnames, keys, container names, connection addresses, or remote payloads are returned.
- SSH config is bypassed with `-F /dev/null`. Absolute, user-owned, nonempty regular trust/key files are required. Every directory is opened relative to its already-verified parent descriptor with symlink following disabled. Ancestors must be root- or current-user-owned and not group/world writable, except root-owned sticky shared directories such as `/tmp`; a private user-owned directory beneath `/tmp` is supported. Leaf permissions prohibit group/world writes to trust and all group/world access to the key. Relative/noncanonical paths, symlink ancestors/leaves, substitution syntax, unsafe ownership and unsafe permissions fail closed.
- Both verified file descriptors stay open through the local trust lookup and all SSH children. Tools receive Linux `/proc/<probe-pid>/fd/<fd>` references to those original inodes, not the supplied paths, so replacing a file or ancestor after opening cannot substitute trust or identity. No trust/key material is copied. Accessible Linux procfs is required; there is no unpinned fallback. This protects against pathname substitution and other-user writes, not a malicious same-UID process or root modifying the original inode in place.
- Host names must be explicit FQDNs or IP literals, not aliases. Existing trust is checked locally with `ssh-keygen -F` (including hashed entries), and SSH itself must verify the presented key. A matching record alone is not proof of a valid remote key or operator approval.
- `StrictHostKeyChecking=yes`, explicit `UserKnownHostsFile`, no global trust fallback, `VerifyHostKeyDNS=no`, and `UpdateHostKeys=no` prohibit enrolling or silently replacing trust. There is no `accept-new`, keyscan enrollment, or fallback route.
- `BatchMode=yes`, public-key-only authentication, `IdentitiesOnly=yes`, `IdentityAgent=none`, zero password prompts, and disabled password/keyboard-interactive/GSSAPI/hostbased methods prevent password automation. Proxy commands/jumps, local commands, agent/X11/port forwarding, PTYs, and multiplexed connections are disabled. Ambient SSH agent/environment configuration is not inherited.
- Local process invocation uses structured argv and `shell=False`. SSH's remote protocol necessarily asks the target's login shell to execute one fixed literal command: `/bin/hostname`, `/usr/bin/uname -s`, `/usr/bin/id -un`, or `/usr/bin/docker --host unix:///var/run/docker.sock ps --all --format '{{.State}}'`. No caller text enters those commands. This does not sandbox a compromised remote host or its configured login shell; use a dedicated restricted metadata account where available.
- Connect timeout is 5 seconds, each command deadline 12 seconds, local trust lookup deadline 3 seconds, at most four checks and no retries. Missing tools, inaccessible Docker socket, encrypted key requiring interaction, or unavailable SSH authentication fail closed. Both subprocess pipes are drained concurrently with nonblocking reads of at most 4,096 bytes. Each stream and their combined total are limited to 16,384 raw bytes while reading; exactly that limit is accepted, and one extra byte detects overflow. Only bounded stdout is retained for parsing; stderr is counted and discarded. Overflow returns the fixed `unexpected_metadata` reason. Timeout, overflow or local read failure kills and reaps only the spawned child, closes pipes and releases pinned files; no process group or discovered PID is signalled. Raw subprocess output is never logged or persisted.
- No `docker exec`, `inspect`, `logs`, environment dump, Compose call, service command, healthcheck, restart, broker process, account endpoint, or execution script exists in this command surface. Docker context/environment routing is bypassed by the fixed local socket.

Tests are isolated standard-library tests in `services/gateway/test_infrastructure_probe.py`. Probe orchestration uses mocked process calls and synthetic trust/key fixtures. Output-limit/deadline/resource-cleanup regressions use local isolated Python children; an additional offline compatibility regression generates an ephemeral synthetic Ed25519 key with `/usr/bin/ssh-keygen` and exercises its key/trust readers against both pinned paths after substitution. No test connects through SSH or calls a broker/network service, reads existing credentials or prints key contents. Coverage includes each stream and the combined byte budget, exact boundaries, continuous output, timeout and read-error cleanup, unsafe ancestors and substitution before child consumption. Parent verification command: `python3 -m unittest discover -s services/gateway -p 'test_*.py'`. Tests were written, not run, during this delegated phase. Parent owns test execution and project gates. Do not run the remote CLI as a test.

## Existing behaviors that must not be conflated

Source evidence is from Gamma Forge's `app/backend/gamma_terminal/live_options/broker_auth.py` and `app.py`, plus legacy vertex-quant's `portfolio-ui/server.mjs`, `portfolio-ui/src/App.tsx`, `vertex-quant/scripts/request-ibkr-2fa-until-ready.sh` (a legacy repository script with no counterpart here), `nautilus/run_live.py`, and `deploy/Caddyfile`. These are reference implementations, not imported routes or a reused legacy BFF. Graph evidence is stale and does not establish these current source behaviors.

**Gamma restart-only control:** `status()` reads local state without contacting Vertex or beginning auth. The mutation uses explicit host trust, a nonblocking lock, and a persisted cooldown of at least 300 seconds. It restarts only the shared Gateway through its scoped remote operation. Its successful response means a restart was requested, with authentication and quote readiness still unverified. The HTTP mutation additionally has transport/Origin/intent/body/operator-password guards. None of that is authorization to call it during research, and a cooldown/timeout response is not a confirmed login.

**Legacy portfolio recovery:** the public manual password-confirmed trigger is POST-only and protected by authentication. Its handler invokes the bounded helper under process-local single flight. The helper checks account readiness, may request a cooldown-gated Gateway restart, then polls while a human approves the phone prompt. Successful legacy recovery also writes a rescan request. The runner has a separate automatic recovery/requeue path after disconnected position state. Preserve/document these rescan and pending-intent effects as distinct behavior; do not silently enable them in the new system.

**Misleading legacy `--check-only`:** it is not read-only. Its readiness call chain can create directories, copy a credential file, start a verification service, connect to IBKR, and write an account snapshot. Even its handshake-only alternative starts that service. Do not wrap it as infrastructure status or run it to check the new probe.

**Other unsafe substitutes:** standby startup starts containers; even its status branch mutates temporary configuration. The watchdog can restart services and create a kill switch. Legacy deployment and healthcheck scripts can source `.env` as shell code. The Gateway Compose configuration has `READ_ONLY_API=no`; paper defaults and application gates are not a broker-enforced read-only connection. Existing source called Nautilus constructs a custom execution runner; package presence is not demonstrated native NautilusTrader engine integration.

## Human recovery requirements for later implementation

Preserve the existing public route/reverse-proxy behavior and explicit “Trigger IBKR 2FA Login” affordance without copying the Gamma frontend or legacy BFF. A new implementation must preserve authentication, POST-only semantics, operator confirmation of exact target/action, secret references, human phone approval, bounded timeouts, persisted cooldown, single-flight ownership, and honest outcome text. Do not reroute other proxy services, broadly recreate the stack, rotate credentials, or remove the Docker-socket dependency without a separately reviewed replacement.

Distinguish restart requested, request delivery uncertain, cooldown, authentication confirmed, and quote readiness. A timed-out request may still be active remotely; do not automatically retry. Login must not auto-arm strategies. Preserve account binding, live gates, kill-switch semantics, position reconciliation, and single execution ownership. No model/JEV proposal may authorize trades, and JEV must never observe financial-service pages or secrets. Automatic recovery, rescan, and pending-intent retries are disabled until separately specified and authorized; restart-only and readiness-plus-rescan are not interchangeable.

## Concrete blockers and stop condition

- Parent's local read-only checks found no entry for the configured Quant VPS endpoint in the default known-hosts file on the rig or the verified alternate Mac route. No trust files were modified; no VPS connection was made. An explicitly configured `GF_LIVE_OPTIONS_KNOWN_HOSTS` alternative, if one exists, remains unverified by this phase and cannot be assumed trustworthy.
- The human operator must establish the exact destination and independently confirm the server host-key fingerprint/trusted route before any infrastructure connection. Never use `accept-new`, an unrelated alias, or the stored SSH password as a shortcut.
- Existing key-based access for the intended metadata account is not verified. This probe does not import keys, unlock keys, alter permissions, add trust, or authenticate with passwords. Required access/trust setup belongs to the human operator.
- Current remote checkout/image/container state, effective runtime, broker login/subscriptions, account binding and native execution engine readiness remain unknown. This phase does not claim a deployed or operational broker integration.
- Historical review material is confined to the ignored, nonexecutable `private/` boundary. Never import it into tests, API fixtures, generated docs, execution payloads, Git, or public evidence. Historical capital and instructions are not current-account facts or present authorization. No executable close/retest rule is defined.

Stop when the local safety boundary, ignored review artifact, and preservation contract are handed off with parent verification pending. Do not connect, recover, deploy, or trade to resolve these blockers during this phase.
