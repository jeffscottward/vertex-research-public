## docs/vertex-rebuild/designs/vertex-viz-liquidity-heatmap/design.md

- **`infra/quant-vps/history/vertex_history.py` (`DepthFeed.read`)**: `design.md` describes
  `DepthFeed.read(since, now, halted=None, off=False)` returning the outer `/depth-history`
  envelope. In the implementation, `DepthFeed.read(self, since, now)` returns
  `{ since, sampleSeconds, rows, snapshots }` and `HistoryService.depth_history` assembles the
  outer envelope, matching the existing `TapeFeed.read` / `HistoryService.tape` pattern.
- **`packages/db/src/schema/flow.ts` & `packages/db/migrations/0093_flow_book_snapshots.sql`
  (`flow_book_snapshots_check`)**: `design.md` wrote an explicit
  `min_tick <> 'NaN'::double precision` predicate; the implemented check uses
  `min_tick > 0 and min_tick < 'Infinity'::double precision`, which rejects `NaN` in PostgreSQL
  because `'NaN'::double precision < 'Infinity'::double precision` evaluates to false.
- **`packages/api/src/server/flow-collect.ts` (level sanitization helper)**: `design.md` named a
  local `sanitizeBookSnapshotLevels` helper in `flow-collect.ts`; the implementation shares
  `sanitizeDepthSide` in `packages/api/src/flow-liquidity-heatmap-rules.ts` so rules and collector
  use one tested sanitizer.
- **`packages/api/src/server/flow-liquidity-heatmap.ts` (repository reads & time bounds)**:
  `design.md` referenced `readLatestSamples(symbol)` and reading from `axisStart`; the
  implementation calls the existing `repository.latestSamples(symbol)` method and reads snapshots
  and large trades from `windowStart - 3 minutes` before deriving `axisStart` from the returned
  capture mode, preventing boundary truncation on the first column.
- **`docs/vertex-rebuild/quantvps-status-endpoint.md`**: Flagged as missing in the drift pass;
  resolved in Commit 6 by documenting `vertex_history.py` `1.7.0`, `209` tests, and
  `GET /vertex-history/v1/depth-history`.
