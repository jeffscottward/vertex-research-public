# Fresh-context design review & resolutions (`vertex-iv-percentile`)

Reviewed `plan.md` and `kb-decision-record.md` against `packages/api`, `packages/db`, and `apps/web` in a fresh subagent context before completing implementation.

| # | Severity | Finding | Resolution applied |
| --- | --- | --- | --- |
| 1.1 | High | `(100 * (max - min)) / (max - min)` overflows `100` to `100.00000000000001` in IEEE 754 float64 for realistic IV pairs (e.g. `0.1038` / `0.13384`), failing Zod `.max(100)`. | Changed formula to `Math.min(100, Math.max(0, ((latest - min) / span) * 100))` and added a regression test with `0.1038` / `0.13384` in `openbb-iv-standing.test.ts`. |
| 1.2 | High | `plan.md` had an internal tension between "newest 252 valid observations" and "newest 252 stored rows where 1 null falls back to proxy". | Standardized on evaluating the newest up to 252 stored sessions (never silently stretching the window across multi-year holes) and falling back cleanly to `vol_index_proxy` whenever a null falls inside that window; updated `plan.md`. |
| 1.3 | High | Widening shared `loadSeries` from 30d to 420d would silently surface >30d-stale closes in `indices` and claim "N stored" when rows fell outside the 420d lookback. | Preserved the 30-day staleness filter on `indices` (`date >= nyDate(-CLOSES_LOOKBACK_DAYS, asOf)`) with a dedicated test case, and worded the proxy shortfall reason honestly as `"Needs 252 sessions of <INDEX> (<N> in 420d window)"`. |
| 1.4 | Medium | Precedence and field values when `latest.atmIv30d === null` needed explicit pinning. | Pinned order (`rows.length === 0` -> `latest.atmIv30d === null` -> `valid.length < 252` -> compute) with `asOf = latest.asOf`, `latestValue = null`, `sessions = validCount`. |
| 1.5 | Low | Avoid unexercised defensive branches in pure helpers to protect 100% coverage. | Documented ascending finite input precondition (enforced by DB checks) and always `.slice(-252)` inside the pure helpers. |
| 2.1 | High | Pin exact Zod schema strictness, `z.literal(252)` for window/min, `z.string().min(1).nullable()` for `reason`, and `nullableFinite` (not `0..10` decimal `iv`) for `latestValue`. | Applied all of these in `packages/api/src/contracts/openbb.ts`. |
| 2.2 | Medium | Clarify `sessions` meaning on `ivDaily` (stored rows) vs `ivOneYear.own` (valid non-null IV rows). | Documented in JSDoc on `OpenbbIvBasisResultSchema`, `mcp.ts`, and `docs/vertex-rebuild/openbb.md`. |
| 2.3 | Medium | Pin parity between `OPENBB_VOL_INDEX_PROXY` and `STRATEGY_IV_INDEX` with strict typing. | Typed with `as const satisfies Record<(typeof OPENBB_CORE7)[number], (typeof OPENBB_VOL_INDEX_IDS)[number]>` and added a parity test in `openbb-iv-standing.test.ts`. |
| 3.1 | High | Proxy-only rows (missing `ivDaily` row) must display `NOT_COLLECTED` ("Not yet collected") in snapshot columns, not `MISSING` ("Not reported by source"). | Kept nullable `asOf` (`string` or `null`) on `IvTableRow` and rendered `NOT_COLLECTED` whenever `row.asOf === null`. |
| 3.2 | High | `<Block id="iv">` header date must include `basisAsOf` so proxy-only rows do not show "Not yet collected" above a populated table. | Added `ivPanelDate(iv)` taking the newest date across `[row.asOf, row.basisAsOf]`. |
| 3.3 | Medium | Preserve canonical `OPENBB_CORE7` row order when combining partial `ivDaily` with `ivOneYear`. | `ivTableRows` iterates `ivOneYear` in canonical order (keeping rows with `daily` or non-null `basis`). |
| 3.4 | Medium | Specify flat-range and unavailable cell text in `IV pctl / rank (1y)` and `1y basis`. | Added `ivStandingText` (`"Not computable"`, `"0 / Flat range"`, `"78 / 64"`) and `ivBasisText` (appending the flat-range `basisReason` after a middle dot). |
| 3.5 | Medium | 7-column Core 7 IV table needs wider `TableScroll minWidth` than `32rem` to avoid cramping at 375 px and 1024 px. | Added optional `minWidth = "32rem"` prop on `DataTable` and passed `minWidth="52rem"` for the Core 7 IV table. |
| 4.1–4.4 | High–Low | 100% coverage gate, knip/Biome unused exports, SVG text sync, OpenAPI/docs/public-names checks. | Verified 100% coverage on all 5 touched/new files, removed unused `ivPercentileText` and `OPENBB_IV_PERCENTILE_MIN_SESSIONS` web import, synced `before-after.svg`, regenerated `openapi.json`. |
