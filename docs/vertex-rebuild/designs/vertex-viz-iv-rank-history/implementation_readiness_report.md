9. **Severity**: Major
   - **Affected Scope**: Section 2 (`Rolling calculation`, steps 3 & 4), lines 121–131; `Testing and verification plan`, line 169 (`packages/api/src/openbb-iv-standing.ts` (lines 63-95)).
   - **Deficiency**: There is an undocumented semantic conflict between `openbbEvaluateOwnIvBasis` and rolling `own` window construction when `openbb_option_iv_daily` contains rows with `atmIv30d === null`:
     - `openbbEvaluateOwnIvBasis` (`openbb-iv-standing.ts` (lines 63-86)) slices the newest 252 **raw rows** (`rows.slice(-252)`) first, then counts non-null `atmIv30d` values; a single null inside the newest 252 rows yields `ivPercentile: null` even if `>= 252` valid rows exist in the fetched history.
     - Step 3 filters `row.atmIv30d !== null` first, then slices `valid.slice(i - 251, i + 1)`. Thus if the newest 252 rows are non-null (so `own_atm_iv` is selected) but an older row at `N - 260` has `atmIv30d === null`, earlier rolling points skip the null gap and span `> 252` calendar sessions—using a different window rule than `openbbEvaluateOwnIvBasis`. In addition, `openbb.optionIvDaily([symbol], asOf, requiredSessions)` limits raw rows (including null-IV rows), so null gaps can cause fewer than `requestedSessions` points to be returned even when older valid rows exist in Postgres.
     - Separately, step 4 specifies `reason` only for `basis === null`, omitting `reason` when `basis !== null` (Section 1 line 92 states `reason` is non-null when `latest.ivRank === null` due to a flat range).
   - **Recommended Fix**: Explicitly specify: (a) the exact rolling `own` gap rule (confirm that pre-filtering `row.atmIv30d !== null` for historical rolling points is intentional while `own` summary / selection stays strictly governed by `openbbEvaluateOwnIvBasis(ownRows)` for parity with `openbb.volContext`, or alternatively align both on raw 252-row windows); (b) that `reason` equals `own.reason` when `basis === "own_atm_iv"` and `proxy.reason` when `basis === "vol_index_proxy"` (null when `latest.ivRank !== null`, even if an earlier historical point had `ivRank === null`).
