Notable changes to DarkFactory will be documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and published releases will use [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Owner market notes (Vertex, research only; card vertex-market-notes): a dated store for narrative market context that the owner sends (reel, article or plain text). Table `market_notes` (migration `0067_market_notes` with app-role grants and a guarded rollback) holds the source, the raw text, one theme line, up to 12 claims with a status each (`unverified`, `supported`, `contradicted`, `cannot-check`, with evidence and check time), the affected sectors, tickers and strategies, a stance and a review date. `marketNotes.add`, `marketNotes.recordChecks` and `marketNotes.review` take the operator write key; `marketNotes.list` and `marketNotes.get` feed the new "Owner market notes" section at the top of `/markets`. The in-app assistant gets the active notes in its system prompt, and research agents read them with the MCP tool `market_notes_list`; every line carries the date and the verification status. A note past its review date shows as stale and is left out of agent context until it is renewed. The rig CLI `vertex-market-note` (`services/research/market_notes`) downloads a reel without cookies, transcribes it on the GPU, extracts the theme and claims, stores the note once per source and prints a Financial Datasets data pack for claim checks. The allocation scripts accept `--market-notes` and report the notes as inputs. Notes never change orders, arming, sizing or risk settings. See [docs/vertex-rebuild/market-notes.md](docs/vertex-rebuild/market-notes.md).
- Breadth-90 signal (Vertex, research only): the rig tick (`vertex-breadth-90.timer`) classifies NYSE up-volume and advancer share per session, alerts ARMED, FORMING, FIRED and THRUST once per channel and pushes sessions, events and status to `breadth90.collect` (operator write key). `breadth90.get` feeds a high-priority card at the top of `/markets` with the state badge, today's values, a 30-session chart with 10/20/80/90% lines, recent events and the dip basket. Migration `0066_breadth_90` with app-role grants and a guarded rollback. See [docs/vertex-rebuild/breadth-90.md](docs/vertex-rebuild/breadth-90.md).
- Cmd+K command palette with parameters (Vertex; card vertex-command-palette): the top-bar palette now runs on cmdk 1.1.1. Besides pages (fuzzy match) and tickers it runs commands with parameters: `chart NVDA 1D` opens `/charts?symbol=NVDA`, `options AAPL 2026-12-19` opens that expiry on the stock page, `NVDA 1W` opens the stock at 1W and `analytics TSLA` the Analytics tab. Tab fills in a command, a wrong parameter shows a hint with the valid forms, and a bare ticker ranks above loosely matching pages. UI lab demo: `/lab/command-palette?q=chart%20NVDA%201D`.
- Research studies in Postgres (Vertex, research only; card vertex-no-json-data): the ADX/RVOL filter study on `/backtests` is now stored in the `research_studies` table (migration `0051_research_studies` seeds it) and read through `researchStudies.get` (operator-only, like Quant Lab) with loading, not-found and error states. The web app no longer ships the study as a JSON file. New runs go `filter_study_summary.py` (prints to stdout) → `bun run vertex:research-studies:import`.
- GEX context strip (Vertex, research only; card vertex-gex-context): the options analytics panel on `/charts` and the stock page Analytics tab shows "Read this before trusting the number" next to the estimated GEX: dealer-sign assumption, OI freshness, expiry mix, regime caveat, spot distance to the estimated gamma flip and call/put walls in one-day implied moves, flow bias, open-interest delta (DEX), estimated dealer vanna and charm with the New York session, IV term regime and the next monthly OpEx. The GEX section also lists the flip and walls. `optionsAnalytics.snapshot` returns the same data as `context`; research agents read it through the new read-only MCP tool `options_gex_context`, and read-access agent keys may call `optionsAnalytics.snapshot`. No new QuantData requests.

Trades Analysis shows win/loss averages, payoff ratio, expectancy, holding times, groups by exit reason and entry weekday, and P/L and holding-time histograms. Trades Log shows the trade replay and the trade list. Under `prefers-reduced-motion: reduce` none of the new motion runs.
- Final JEV order gate on live orders (Vertex, merge plan P6; owner approval 2026-11-05): the gate now runs on every order review and submit, simulated and live, and takes the account gates (kill switch, OPTIONS_ONLY) as inputs. Live single-leg orders get the call/put choice. Opening verticals stay on the simulated gateway: the live order tail (market-watch-bot `ops/vertex_order_tail.py`) accepts exact combo closes only, so a live opening combo is refused by the close-only rule. A live new position needs a fresh JEV verdict (refresh it on /charts first); closes still pass without one and with the kill switch on. A placement the gateway refuses (for example "aborted") is now audited as a failure. VERTEX_ORDERS_ENABLED and VERTEX_ORDER_SUBMISSION still select the live bridge.
- Final JEV order gate wired into the order screen (Vertex, merge plan P6, simulated/paper gateway only): `vertexOrders.preview`, `.submit`, `.comboPreview` and `.comboSubmit` run `evaluateFinalOrderGate` with the cached P5 JEV verdict and the fresh account snapshot, and every review carries a new `finalGate` field (decision, structure, max loss and % of account, JEV stance and state, reasons). A deny blocks the confirm token. "Risk-reducing" is now derived from held positions, never a caller flag. The order screen has a call/put choice and a new vertical spread ticket (one combo order, net debit or credit); opening verticals are accepted only on the simulated gateway, and an opening debit vertical counts against the same per-name premium caps as a long option. A risk-reducing order sent without a fresh JEV verdict is recorded in the order audit (`finalGate` attribute). Live mode is unchanged: `finalGate` is null and combos stay close-only until the owner approves moving the live gates. The mock gateway seeds a second cancellable option order for the E2E cancel flow.
- Final JEV order gate (Vertex, merge plan P6, step 1; not wired into any order path yet): the pure function `evaluateFinalOrderGate` in `packages/api/src/server/final-order-gate.ts` answers allow or deny for one exact order. It accepts only a long option, a debit vertical or a defined-width credit vertical (no shares, no naked or ratio shorts), denies a max possible loss above 2% of account value or an unknown account value, and denies a missing, stale, unreachable or opposing P5 JEV verdict. Risk-reducing orders are allowed when JEV is unreachable. It never changes size or price and reads no environment.

- Linux support for the operator plane. OMP and git run in a bubblewrap sandbox with the same filesystem scope as the macOS `sandbox-exec` profile: scopes read-only, writable only in implementation runs. The worker checks `bwrap` and user namespaces before each run and fails closed. See `docs/operator.md`.
- On Linux the agent and git cannot start other processes, as on macOS. bubblewrap loads a seccomp filter under which `fork`, `vfork` and any `clone` that is not a thread fail with `EPERM`; threads still work. `git worktree add`, which runs git itself, is the one exception. Before each run the worker checks that the filter stops a test process from starting, and fails closed; the filter supports x86_64 and arm64. See `docs/operator.md#platform-support`.
- On Linux the agent has no network and holds no credentials. Each run reaches exactly one model through a relay to a local `omp auth-gateway`, which gets credentials from `omp auth-broker`. DarkFactory pins no model: `WORKFLOW_OMP_MODEL` names yours, and planning, implementation and review all use it. Configure it with `WORKFLOW_OMP_GATEWAY_URL` and `WORKFLOW_OMP_GATEWAY_TOKEN_FILE`; the worker refuses to start with a gateway but no model. Before each run the worker checks the gateway, the model and `nsenter`, and fails closed. See `docs/operator.md#models-and-credentials`.
- The Docker verifier reaches rootless Docker, or any local daemon, through `DOCKER_HOST`. Only local unix sockets are accepted.

### Changed

- Coverage uses ast-v8-to-istanbul 1.0.8: the pnpm override that held it at 1.0.5 is removed. Since 1.0.7 it also counts functions and branches inside logical expressions (`a && b.map(…)`, `x ?? y`), and 1.0.8 no longer reports static class methods as always covered. New tests cover the newly counted code, so no file of the coverage ratchet lowers its minimum. (card vertex-cov-astv8-107)
- Design system: DarkFactory now looks and behaves like shadcn/ui (new-york-v4). Themes use shadcn's exact CSS variables (`background` … `sidebar-ring`, `--radius`) through Tailwind v4 `@theme inline`; `success`, `warning`, `info` and `destructive-foreground` are documented extensions, and the older names (`surface`, `primary-subtle`, …) are derived from them. Fonts are Geist Sans and Geist Mono (bundled; Manrope and Public Sans are removed). Defaults equal shadcn: radius `0.625rem`, `--spacing` `0.25rem`, Tailwind type scale, `text-sm` UI text. Button, Input, Textarea, Label, Card (new `CardAction`), Badge, Separator, Skeleton, Avatar, Tabs (new `line` variant), DropdownMenu (new `DropdownMenuShortcut`, destructive items) and Dialog use shadcn class strings; a new `@darkfactory/ui/client/sidebar` ports the shadcn Sidebar. Controls keep the 44px touch-target box around shadcn-sized chrome; inputs are 44px tall. See `design-system/darkfactory/MASTER.md` sections 3 and 7.
- Portal shell: shadcn sidebar-07 / dashboard-01 anatomy. An inset sidebar (16rem) collapses to icons (3rem) with the trigger, the rail or Ctrl/⌘+B. ## [0.3.1] - 2026-09-29

Security fix release. Covers [#40](https://github.com/jeffscottward/darkfactory/pull/40), [#43](https://github.com/jeffscottward/darkfactory/pull/43), [#46](https://github.com/jeffscottward/darkfactory/pull/46), [#47](https://github.com/jeffscottward/darkfactory/pull/47) and [#48](https://github.com/jeffscottward/darkfactory/pull/48). If you built the operator verifier image with 0.3.0 or earlier, follow the rebuild steps under Security.

### Changed

- Pre-push takes about 37 s instead of about 80 s. The init clone acceptance test (clone, init, install) moved to its own `acceptance` Vitest project, which the CI coverage lane runs with coverage; run it locally with `bun run test:acceptance`. (#48)
- Test tooling: jsdom 30 and `@testing-library/react` 16.3.3. (#43, #40)

### Fixed

- The pre-push hook accepts Git's empty input, which Git sends for "Everything up-to-date" and for pushes it already rejected (stale lease, non-fast-forward). It used to fail with "expected four fields" and hide Git's own message. (#47)
- The verifier's `build-web` check points at `apps/web`'s `vinext` binary, and the image makes its dependencies readable for the runtime user regardless of the builder's umask. (#47)
- Two load-dependent test flakes (#46): an isolated RSC build test now runs the plugin hook that initializes `es-module-lexer`, and an operator test waits for run details to load.

### Security

- The operator verifier image leaked local secrets. Its `Dockerfile.dockerignore` re-included whole `apps/` and `packages/` subtrees, so each app's `.dev.vars` (which holds every non-empty value from `.env`), other `.env*` files and host `node_modules` were copied into the image. `.dev.vars` stayed root-only in the image, so code under verification (uid 65532, no network) could not read it; anyone with access to the image can. World-readable `.env*` files there were readable in the container, with `/output` as the only way out. The allowlist now names files only, and an invariant test rejects directory re-includes. (#47)
- The verifier image fetches pnpm as a checksum-pinned registry tarball instead of an unpinned `npm install --global`, and its Bun base defaults to a digest-pinned `oven/bun:1.3.14`. `DARKFACTORY_VERIFIER_BASE_IMAGE` is now an optional override, which must still be digest-pinned. (#47)

To remove the exposure, rebuilding is not enough: the worker keeps running the image pinned in `.env`.

1. Run `pnpm --filter @darkfactory/jobs verifier:image:setup`, set the printed digest as `WORKFLOW_VERIFIER_IMAGE_DIGEST` in `.env`, then restart `worker:pilot`.
2. Delete every other verifier image. A rebuild untags the old one, so list them by label: `docker image ls --filter label=org.darkfactory.verifier.identity`, then `docker image rm` each ID except the new digest. Remove old images from any registry too.
3. Rotate the credentials from `.env` if an old image was exported, pushed or shared, and any real secrets in other `.env*` files under `apps/` or `packages/`.
